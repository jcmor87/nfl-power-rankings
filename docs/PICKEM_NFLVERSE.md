# nflverse schedules and scores

**Decision.** The published nflverse schedules release is a viable candidate for automated schedule snapshots and provisional scores. Use an explicit, independently confirmed NFL final or cancellation before disclosing picks, finalizing the week or sending results. The schedule CSV alone cannot distinguish those states reliably.

## License and access

The official [nflverse schedules release](https://github.com/nflverse/nflverse-data/releases/tag/schedules) documents downloading its CSV through nflreadr and nflreadpy. The release repository publishes [CC BY 4.0](https://github.com/nflverse/nflverse-data/blob/main/LICENSE.md), whose grant permits copying and adapting licensed material, including licensed database rights. This supports programmatic consumption of the published asset within the rights the publisher can grant. Keep attribution to nflverse and Lee Sharpe, link the release and license, and identify transformations such as timezone conversion if data are shared. The schedule release credits [Lee Sharpe’s upstream repository](https://github.com/nflverse/nfldata), where this review found no separate repository license. nflverse’s package documentation reserves other owners’ rights in underlying datasets. Confirm any schedule-specific or upstream permissions with the maintainers before publicly redistributing or depending on rights beyond the release. Use the published asset through documented download channels and observe GitHub rate limits and terms. No ESPN access was used for this review. | Historical corrections | The [release workflow](https://github.com/nflverse/nfldata/blob/master/.github/workflows/release_games.yml) upserts changed values by `game_id`. That can carry corrections for the same key and can retain an old key when an identity changes. Comparing a December 23, 2025 upstream snapshot to the current release found no changed score pairs among matching previously scored rows. No actual score correction or correction deadline was verified. Retain snapshots and send changes to prior verified results for manual review. [Historical snapshot](https://github.com/nflverse/nfldata/blob/b56d5f6ad161a1e435c704bcffb304026205d33c/data/games.csv) |
| Game identifiers | `game_id` was unique in each sampled season and stayed stable in the same-week flex example. It embeds season, week and team codes, so use it as a source alias. In 2026 `gsis` was present for 163 of 272 rows and `nfl_detail_id` was empty for all 272. Keep an internal game ID and explicitly reconcile changed weeks, team codes or source aliases before updating matches with existing picks. | In-season availability | The published asset downloaded without a paid account. The release timestamp was 3:17 p.m. Pacific on November 24, 2026. nflverse documents five-minute in-season updates, while recent upstream commits sampled that day were 10–20 minutes apart. The release workflow republishes on changed input and GitHub delivery adds another dependency. Full-season uptime and a freshness SLA are unverified. ## Free fallback and verification

Use owner-reviewed entry of matchup facts from official NFL weekly schedules, Game Centers and league announcements. Record the official evidence URL, who verified it and when in the audit log. If the nflverse file is unreachable, stale, contradictory or missing a matchup, retain the last trusted snapshot and keep affected picks or results on hold as appropriate. After manual confirmation, apply the official kickoff or terminal state to the existing canonical game. Preserve recorded starts, and reread a completed week after corrections before recalculating. A missing row never authorizes a cancellation or result disclosure.

An unattended fallback requires a provider that explicitly permits scheduled access and exposes status, corrections and stable IDs. No free source meeting all three requirements was confirmed. This PR adds no scheduled fetch or release ingestion.
